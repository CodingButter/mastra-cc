# 0073 — A query scope narrows authority

- **Status:** accepted
- **Date:** 2026-09-04
- **Schema:** 1.14.0
- **Related:** ADR-0068 (application authority follows verified names), ADR-0069 (application names are case-folded), ADR-0071 (incomplete observation is not absence)

## Context

`queryElements` could filter by element role and name, but every permitted application still shared one result set. Common labels such as “Open” could therefore arrive from unrelated applications, and browser work required the caller to infer ownership from a global desktop reading. That inference is not authority: the daemon is the component that owns grants, backend identity, visibility, and connection-local element IDs.

The public request schema must express useful narrowing without allowing caller-provided names to reveal an ungranted application or silently widen a query when a requested scope cannot be established.

## Decision

Schema version 1.14.0 adds optional `application` and `window` strings to the existing `queryElements` request. They are exact normalized names, not element IDs. `application` selects one currently visible and authorized application. `window` selects one currently visible window inside that application and is valid only when `application` is present.

The generated schema owns field types and additional-property rejection. The daemon owns the cross-field rule and backend authority. A selector only narrows the roots a backend may inspect; it never grants visibility, changes `listApplications`, or converts a name into durable element authority. Missing, ungranted, unreadable, or ambiguous scopes are indistinguishable empty answers. Once traversal of a selected scope begins, budget exhaustion remains an incomplete-observation refusal rather than false absence.

Application comparison follows the existing NFKC and case-folded application-name rule. Window and element names remain exact after NFKC normalization. AT-SPI, CDP, and replay retain their own native liveness and identity models; replay must consume captured evidence rather than inventing a scope.

## Consequences

- Callers can isolate duplicate element names without receiving a mixed global result set.
- Authorization remains daemon-owned and deny-by-absence; selectors cannot become an existence oracle.
- Old requests containing only `role`, `name`, and `limit` remain valid and serialize unchanged.
- The protocol schema changes additively, requiring regenerated golden output and a minor version bump.
- A window cannot be queried independently of its application. This is intentionally less convenient than a global title lookup because duplicate titles are common and application authority must be resolved first.
- Names remain observations, not durable identities. Navigation still requires a fresh query and fresh connection-local element IDs.

## Evidence

- `protocol/schema.json` defines the two optional fields and schema version 1.14.0.
- `protocol/golden/` is regenerated by `node protocol/generate.mjs` and checked by the freeze, determinism, digest-agreement, and catalog gates.
- Desktop package tests pin generated client and Mastra-tool acceptance of both selectors and rejection of malformed field shapes.
- Backend enforcement, cross-field refusal, grant isolation, ambiguity handling, and replay behavior are proved in the following implementation phase.
