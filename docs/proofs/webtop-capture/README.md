# Webtop X root-window capture diagnosis

**Diagnosis, not a screenshot fix.** On September 26, 2026, the benchmark container's KDE Wayland/Xwayland desktop rejected `xwd -root -silent` with `BadMatch` at `X_GetImage`. The same executable and desktop user captured an isolated Xvfb screen successfully. The failure precedes the daemon's image decoding and cropping.

## Reproduce without a model

From the repository root, against the existing benchmark container:

```sh
DOCKER_HOST=unix:///var/run/docker.sock python3 docs/proofs/webtop-capture/probe.py mcc-bench
(cd docs/proofs/webtop-capture && sha256sum -c SHA256SUMS)
```

The host needs Python 3 and Docker access. The container needs its running KDE session, desktop UID 1000, Python GI (`Gio`/`GLib`), `xwd`, `xvfb-run`, `pgrep`, `ps` and `timeout`. These were already present; this proof installs nothing. Use another container name as the positional argument. An explicit `DOCKER_HOST` is respected; otherwise the script supplies the system socket. Docker's own precedence still applies: unset `DOCKER_CONTEXT` when selecting a host with `DOCKER_HOST`. This workstation's inherited rootless socket was unavailable: connection failure is a setup failure, not evidence about screenshots.

Expected final line: `DIAGNOSIS: VERIFIED (not a screenshot fix); pixels discarded`. Any changed prerequisite, unexpected capture result or authorization result exits nonzero and requires revisiting the diagnosis. A nonexistent container must also exit nonzero:

```sh
DOCKER_HOST=unix:///var/run/docker.sock python3 docs/proofs/webtop-capture/probe.py mcc-capture-no-such-container
```

The script selects exactly one desktop-user `plasmashell`, copies only the display/session connection variables from its environment, and does not print the session bus address or full environment. Capture commands have eight-second limits; D-Bus calls have eight-second limits; helper commands have twelve-second limits; the in-container diagnostic has a 45-second limit with three-second kill escalation and the host waits at most fifty seconds for `docker exec`. Termination unwinds active helper calls and kills their process groups. The nonexistent-container control tests setup failure only, not every unexpected-result branch. Xvfb is temporary and isolated, not a replacement for the benchmark desktop. Pixel output uses private temporary files and is discarded, never committed. No desktop apps are stopped, permission configuration changed, or model requests sent.

## Measured results

See [probe.txt](probe.txt), generated by [probe.py](probe.py).

| Probe | Result | What it establishes |
|---|---|---|
| Desktop-user process inventory | `kwin_wayland`, `Xwayland` | This observed session is not an Xvnc desktop |
| Actual desktop, UID 1000, `xwd -root -silent` | Exit 1, zero bytes, `BadMatch`, `X_GetImage` | The acquisition command used by the daemon fails before it produces pixels |
| Same UID and binary, isolated Xvfb | Complete XWD v7, 160×120, depth 24, 79,979 bytes | `xwd` itself can produce a complete image; the decoder checks are not needed to explain the desktop failure |
| KDE `ScreenShot2` introspection | `CaptureWorkspace` advertised | A compositor-owned screenshot interface exists |
| KDE `CaptureWorkspace` with a valid passed file descriptor | `org.kde.KWin.ScreenShot2.Error.NoAuthorized`, zero bytes | **This diagnostic caller** lacks authorization; other callers were not tested |
| Desktop portal introspection | `org.freedesktop.DBus.Error.ServiceUnknown` | The portal service was neither owned nor activatable in this session at probe time |

A preliminary root-user call failed X authentication instead. It is deliberately not the reproduction: the committed script uses the desktop user, like the benchmark. The committed probe verifies exactly one Xwayland process serves the selected display and carries `-rootless`; it prints only the boolean result, not unrelated command arguments.

The transcript records the configured image digest, not a pristine-image guarantee. This is the existing benchmark container and includes earlier harness provisioning (including `kinfocenter`). No claim is made that every installation of that image or every rootless Xwayland server behaves identically.

## Scope decision

The current acquisition implementation in [capture.ts](../../../daemon/src/backends/atspi/capture.ts) invokes `xwd -root -silent` and then decodes XWD. It has no compositor/portal fallback. Changing crop math, retrying unchanged, or renaming the refusal would not address the observed failed acquisition. The existing `world/UnperformableElementError` remains unchanged; it reports the attempted route's refusal, **not proof that screenshots are inherently unavailable or that applications are at fault**.

A Wayland capture implementation would be a separate feature requiring an explicit authorization path, bounded file-descriptor/image handling, cancellation, desktop coordinate/scaling correspondence, occlusion semantics and real compositor proof. This diagnosis does not install a portal, impersonate an authorized KDE client, bypass permissions, or add that feature. It does not claim that an authorized compositor capture has succeeded.

The historical [Webtop benchmark](../benchmark/webtop/README.md) remains **29/30 tasks passed** with thirteen capture refusals. No run, score or recorded refusal was rewritten. Successful task runs did not establish working screenshot support. We also cannot infer that fixing capture alone would make bad-page run 4 pass.
